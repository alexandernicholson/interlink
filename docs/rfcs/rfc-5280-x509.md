## Abstract

Profiles X.509 v3 certificate format for Internet use. Defines certificate fields, standard extensions, certification path validation, and CRL profile. For interlink, critical sections are SAN encoding (§4.2.1.6) for SPIFFE identity, and path validation (§6) adapted for short-lived certs.

## SPIFFE ID in SAN

Per §4.2.1.6:2030-2038, the SPIFFE identity is encoded as a `uniformResourceIdentifier` in the `subjectAltName` extension:

```
URI: spiffe://<trust-domain>/ns/<namespace>/sa/<service-account>
```

When the only identity is in SAN, the subject DN MUST be empty (§4.2.1.6:1982-1985) and SAN MUST be marked critical.

## Serial Number Entropy

Per §4.1.2.2, certificate serial numbers MUST be unique and contain at least 20 octets (160 bits) of entropy when using non-cryptographic random number generators. interlink generates 20-byte serial numbers for both root and leaf certificates.

## SPIFFE ID Validation

interlink enforces SPIFFE ID structure at parse time and rejects:
- Empty trust domain, namespace, or service-account segments
- Malformed URI schemes or missing path components
- Wildcards in the trust-domain segment

The policy engine supports partial wildcards in namespace and service-account segments (e.g., `spiffe://cluster.local/ns/team-*/sa/*`).
