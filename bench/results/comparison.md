# Service Mesh Benchmark Comparison

Generated by `bench/scripts/aggregate.py`. All meshes run on the **same** 3-node kind topology (`bench/manifests/kind-3node.yaml`): load generator and echo server pinned to separate worker nodes so mesh traffic crosses the node boundary. Identical workload (Go echo server, 200 ms fixed delay, 1 KB payload), identical Fortio load, CPU/memory sampled via `kubectl top pod`.

A profile is **valid** only if the achieved RPS was within 3 % of target, there were zero errors, and peak host CPU stayed below 85 %. Invalid profiles are host-bound (the machine, not the mesh, was the bottleneck) and are excluded from the comparison below — rerun on a less loaded / dedicated host.
