## Analysis

### Proxy overhead (latency above 200 ms base)

| Mesh | Light (320 RPS) | Medium (3,200 RPS) | Heavy (12,800 RPS) |
|------|----------------|-------------------|--------------------|
| interlink | +2.9 ms | +9.2 ms | +25.1 ms |
| Linkerd | +13.5 ms | +99.2 ms | +495.5 ms |
| Istio ambient | +9.1 ms | +49.7 ms | +147.2 ms |

Interlink adds the least latency overhead across all profiles. Istio ambient is roughly 2-3x lower overhead than Linkerd.

### Resource efficiency (heavy profile)

| Metric | interlink | Linkerd | Istio ambient |
|--------|-----------|---------|---------------|
| Actual RPS / target | 99.6 % | 92.7 % | 99.9 % |
| p99 latency overhead | +25.1 ms | +495.5 ms | +147.2 ms |
| Proxy CPU (relative) | 1× | ~25× | ~9× |
| Proxy memory (relative) | 1× | ~6× | ~2× |

### Key takeaways

1. **interlink** is the lightest-weight mesh, with negligible latency overhead and minimal resource consumption.
2. **Istio ambient** (ztunnel) is highly efficient — roughly 3× less CPU and 4× less memory than Linkerd at heavy load, while maintaining full throughput.
3. **Linkerd** (sidecar) struggles at high connection counts, with 7 % throughput loss and 495 ms p99 overhead at 12,800 RPS.
4. All meshes sustained 0 errors across all profiles.

## Reproduce

```bash
# Local interlink only
cd bench/local && ./run.sh

# Full Kubernetes comparison (requires kind + kubectl)
cd bench/
./setup.sh          # installs pinned tools
./scripts/run-linkerd.sh
./scripts/run-istio.sh

# Interlink on Kubernetes (requires built interlinkd image)
./scripts/run-interlink.sh

# Clean up
./teardown.sh
```
